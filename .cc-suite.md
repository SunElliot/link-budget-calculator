## Project-Specific Instructions

Custom instructions appended to Codex's developer-instructions for every command.
Use this to tell Codex about your project's conventions, architecture, or constraints.

```text
This is a vanilla HTML/CSS/JavaScript static site served from GitHub Pages.
There is no build step, no bundler, and no package manager — every page loads
its scripts directly, so any suggestion that introduces a build pipeline,
a framework, or an npm dependency is out of scope unless explicitly asked for.

The site is a set of sibling single-purpose calculator pages at the repo root
(link-budget.html, antenna.html, doppler.html, rain.html, …). They share
i18n.js, a11y.js, share.js, linkout.js, modcod.js and styles.css. Because the
pages are near-duplicates of one another structurally, the dominant risk in
this codebase is drift: the same fix applied to one page and not the others,
or shared behaviour re-implemented inline instead of being lifted into the
shared scripts. Weight duplication and cross-page inconsistency accordingly.

sw.js is a service worker and manifest.json/sitemap.xml/robots.txt are
deployment metadata — judge them against static-hosting conventions, not
application-code conventions. vendor/ holds third-party code and is skipped.
```
